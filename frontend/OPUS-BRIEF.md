# Opus 前端作业契约

> 这份文档解决的问题不是「哪个模板好看」，而是：**为什么 Opus 一写前端就长成同一个样子，以及怎么让它在这个项目里不长成那个样子。**

---

## 0. 先接受一个事实

Anthropic 官方文档把这个现象叫 **distributional convergence（分布收敛）**：

> 模型按训练数据里的统计规律预测下一个 token。而"安全的"设计选择在互联网上占绝对多数，所以**提示词一旦不充分，采样结果就会落回中位数**。

中位数长什么样，官方 `frontend-design` skill 直接点名了三簇：

1. 米白底 + 衬线大标题 + 赤陶色点缀
2. 近黑底 + 荧光绿单色
3. 报纸式细线 + 密集分栏

Opus 4.8 之后需要的提示已经比旧版短很多，但**"做一个好看的页面"这句话本身就是在要求平均值**。所以：

- ❌ 说「现代、简洁、有设计感」→ 拿到中位数
- ✅ 说「近黑底 #08090A、1px 发丝线、零圆角、等宽数字、字重不超过 600、禁止紫色渐变」→ 拿到你要的

**泛泛的"避免 AI 味"是无效指令**，官方原话是：那只会让它从一种默认风格换成另一种默认风格。必须**点名不要什么**。

## 1. 这个项目里的三层防线

| 层 | 文件 | 作用 | Opus 能不能改 |
|---|---|---|---|
| 令牌 | `frontend/css/tokens.css` | 11 个颜色、7 档字号、3 条缓动 | **只能改这里**，且要说明理由 |
| 组件 | `frontend/css/theme.css` | 所有组件的唯一实现 | 可加，不可改已有类 |
| 参照 | `frontend/kit.html` | 所有组件的可视化全集 | **只读**，不许改 |

配套：`shared/check-ui.mjs` —— 改完跑一遍，机器判定是否跑偏。

```bash
node shared/check-ui.mjs          # 0 error 才算过
```

它查的不是偏好，是**每一条都真实踩过的坑**：

| 规则 | 为什么存在 |
|---|---|
| `no-hex-outside-tokens` | 颜色一旦散落，改主题就是全文件搜替 |
| `no-generic-font` | Inter / Roboto / Arial 是官方点名的第一个 AI slop 特征 |
| `no-heavy-weight` | 字重 700+ 会立刻把细字重的终端感打回 SaaS 风 |
| `no-radius` | 圆角只许 0 / 50% 状态点 / 主 CTA 10px |
| `no-slop-gradient` | 紫蓝渐变 + 渐变文字 = 一眼生成物 |
| `no-emoji` | 投影仪上会糊成一团 |
| `temp-transition-too-slow` | **价格变色写过 0.8s，比 400ms 的跳动还慢，颜色永远追不上价格** |
| `price-needs-tabular` | 缺 tabular-nums，数字每秒跳一次宽度就抖一次 |

## 2. 粘贴即用的作业指令

### 第一次：定方向（不改代码）

官方推荐的做法是**先要 4 个方向，人选一个，再写码**。把这段直接发给 Opus：

```
读 frontend/kit.html 和 frontend/css/tokens.css，不要改任何文件。

在动手前，先给我 4 个视觉方向（每个一行）：
格式：底色 hex / 主强调 hex / 字体组合 —— 一句为什么适合"信息随时间贬值"这个产品。

要求：4 个方向必须彼此不同，且都不是这些默认簇：
米白+衬线+赤陶 / 近黑+荧光绿 / 报纸细线分栏。
```

### 之后：每次只改一页

```
任务：把 frontend/s.html 接到 theme.css 的视觉上。只改这一个文件。

先读：frontend/kit.html（组件全集）、frontend/css/tokens.css（令牌）。

规则：
- 颜色只能 var(--*)，禁止新 hex
- 字号只能 var(--t-*)
- 已有类名不改名，不改 theme.css 里已有规则
- 圆角只用 0、50%、var(--r-cta)
- 动效只有三处：数字逐位抖 120ms、价格变色 280ms、面板展开 450ms
- 不许加：卡片阴影、渐变、图标 emoji、居中大标题+双按钮的落地页结构

不要顺手重构 HTML 结构，不要动 js/ 里的逻辑。
改完跑 node shared/check-ui.mjs，把输出贴给我。
```

### 收尾：自检（这一步 90% 的人会跳过）

> 让 Opus 自己看截图挑错，比让它继续写有效得多。

```
截图（或你看到的渲染）对照下面 7 条，逐条打勾或指出问题，不要改代码：
1. 3 米外能不能读出价格这一个数字？
2. 页面里有没有超过 2 个不同圆角？
3. 有没有任何一处颜色是硬编码的、不是 token？
4. 数字是不是等宽 + tabular-nums（跳动时宽度不抖）？
5. 去掉所有动效，页面还成立吗？（成立才是对的）
6. 有没有哪个元素是"为了好看"加的、删掉不影响信息？
7. 如果把这页给没听过这个项目的人看，他 3 秒内能不能说出"这是个什么"？
```

## 3. 十二个典型翻车与修法

| Opus 会做的 | 为什么不行 | 怎么让它改 |
|---|---|---|
| 给价格加 `text-shadow` 发光 | 投影下发光会糊，且抢走"温度"信号 | 明令禁止；要强调就换字重/字号 |
| 价格数字用 `font-weight: 700` | 破坏 250 细字重的终端气质 | 字重上限写进指令 |
| 加载时加骨架屏 shimmer | 这产品永远有数（本地插值），不需要骨架屏 | 说明"永远有值可显示" |
| 给按钮加 `border-radius: 999px` 胶囊 | 与零圆角体系冲突 | 已写进 check-ui |
| 用 emoji 当 KPI 图标 | 投影糊、审美的廉价信号 | 已写进 check-ui |
| 把 `#08090A` 直接写进组件 | token 失效，改主题要全搜 | 已写进 check-ui |
| 价格变色写 `transition: .8s` | **颜色追不上 400ms 的跳动** | 已写进 check-ui |
| 数字不加 tabular-nums | 每秒跳一次、宽度抖一次 | 已写进 check-ui |
| 给收据加"卡片 + 阴影" | 收据应当像小票，不像 App 卡片 | 参照 kit.html 第 07 节 |
| 加"← 返回"图标 + 面包屑 | 单页产品不需要导航层 | 说明信息架构只有 4 页 |
| 把标题居中 + 副标题 + 双 CTA | 最典型的落地页模板 | 明令禁止该结构 |
| 自作主张加暗色/亮色切换 | 现场投屏只有暗底可用 | 说明"没有浅色模式，是设计决定" |

## 4. 三个可直接抄的开源仓库（只抄排版，不抄组件）

| 仓库 | 抄什么 | 不要抄 |
|---|---|---|
| `vercel/geist-font` | **字体本体**（SIL OFL 可商用）：Geist Sans + Geist Mono | — |
| `maybe-finance/maybe` | **金额排版**：大数字用细字重 + 等宽 + 右对齐 | Ruby 技术栈 |
| `OpenBB-finance/OpenBB` | **终端密度**：行高、分隔线、极简色 | 组件结构 |

> 注意：`tokens.css` 里的 `--num` / `--ui` 已经预留了 Geist。把 woff2 放进 `frontend/fonts/` 并在 `tokens.css` 顶部加 `@font-face` 即可，**其余文件一行都不用改**——这就是 token 化的好处。

## 5. 文件清单

```
frontend/
  css/tokens.css      ← 唯一可改的颜色/字号/缓动
  css/theme.css       ← 组件实现（4 页共用）
  css/base.css        ← 兼容层，只 @import，页面 HTML 不用改
  kit.html            ← 组件全集，Opus 的参照物（只读）
  js/price.js         ← 价格格式化 + 逐位跳动（视觉层唯一新逻辑）
shared/
  check-ui.mjs        ← 漂移检查器，改完必跑
```

四个页面（`index / publish / s / live`）**HTML 一行没改**，视觉从 `base.css` 自动生效。
唯一新增的开关：`live.html?id=1&static=1` 不建 SSE，供截图与设计评审。
